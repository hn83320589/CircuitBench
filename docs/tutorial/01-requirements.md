# 01 需求分析

## 背景與目標

> 📄 依據：需求規格「客戶背景」

一位高職電子科的老師希望學生在沒有實驗器材時，也能在電腦上畫電路、量電壓、看波形。市面上的模擬軟體多為英文、操作繁複，學生畫錯電路時只會看到看不懂的錯誤訊息。她要的是**離線、中文介面、會清楚告訴學生「哪裡接錯了」**的桌面工具。

從這段背景可以讀出三個貫穿全案的設計重點：

1. **錯誤訊息是功能，不是附屬品**：每一種錯誤都要用中文指出元件或節點，並在圖上標示。這影響了資料模型：`CircuitIssue` 帶有 `ComponentNames` 與 `Nodes`，UI 才能畫紅框（見 `src/CircuitBench.Core/Validation/CircuitValidator.cs`）。
2. **離線**：不能呼叫外部網路服務，所有數值計算都在本機完成。
3. **給學生用**：預設值就要給出正確的結果，學生不會去調步長或容許值。這一點在審查回饋後變得更明確，見 11 章「預設設定也要準確」。

## 使用者與角色

| 角色 | 說明 | 來源 |
|---|---|---|
| 學生 | 主要使用者：畫電路、執行分析、看波形與量測值 | 📄 需求規格 |
| 老師 | 準備範例電路（專案檔或 SPICE 網表）讓學生開啟 | 🔍 推斷：需求規格要求「範例電路」與 SPICE 匯入匯出，但沒有明確描述老師的操作流程 |

系統是**單機、單一使用者、單一程式執行個體**（📄 需求規格「其他」），所以沒有登入、權限或多人協作。

## 功能需求

| 編號 | 需求 | 來源 |
|---|---|---|
| FR-01 | 格點畫布上放置元件、拉導線、旋轉與鏡射、移動、刪除、複製貼上；元件名稱與參數可編輯 | 📄 需求規格 |
| FR-02 | 連線規則：導線端點落在另一導線中段時自動產生接點；交叉無接點不相連；接腳與端點同格點即相連；同名網路標籤為同一節點；接地為節點 0 | 📄 需求規格 |
| FR-03 | 由圖面萃取網表，並標出未連接的接腳 | 📄 需求規格 |
| FR-04 | 復原與重做至少 100 層；縮放、平移、框選、對齊格點 | 📄 需求規格 |
| FR-05 | 元件：R、C、L、獨立 V／I（DC、SIN、PULSE、PWL，另設交流振幅與相位）、二極體、E、G、時間切換的理想開關、接地 | 📄 需求規格 |
| FR-06 | 參數接受工程記號（`4.7k`、`10uF`、`1meg`；`m` 一律為毫） | 📄 需求規格「假設事項」 |
| FR-07 | 分析前做電路檢查：無接地、浮接節點、電壓源與電感迴路、未連接接腳、參數無效；中文指出元件或節點，並在圖上標示 | 📄 需求規格 |
| FR-08 | 元件名稱重複的檢查 | 🔍 推斷：規格未列出，但 `IssueCode.DuplicateName` 存在。推測是因為 SPICE 以名稱識別元件，重名會讓網表無法往返 |
| FR-09 | 直流工作點：MNA + Newton-Raphson；失敗時依序 gmin 步進、電源步進；全部失敗時回報最後未收斂的節點 | 📄 需求規格 |
| FR-10 | 直流掃描一個獨立電源 | 📄 需求規格 |
| FR-11 | 暫態分析：從直流工作點開始、可變步長、依 LTE 接受或拒絕；轉折點與開關切換時刻必須剛好落在時間點上 | 📄 需求規格 |
| FR-12 | 交流分析：在工作點線性化後解複數 MNA，線性或對數掃描 | 📄 需求規格 |
| FR-13 | 分析在背景執行、可取消、回報進度；取消後不留下半套結果 | 📄 需求規格 |
| FR-14 | 自行實作稀疏 LU（實數與複數），部分主元，結構不變時重用符號分解，偵測奇異 | 📄 需求規格 |
| FR-15 | 波形檢視器：任意節點電壓與支路電流、多曲線、多 Y 軸、縮放平移、自動縮放 | 📄 需求規格 |
| FR-16 | 大量資料點以「每像素欄的最小值與最大值」抽樣，任何縮放都不遺漏尖峰 | 📄 需求規格 |
| FR-17 | 兩條游標：Δt、ΔV、1/Δt；區間平均值、RMS、峰對峰值、頻率（內插零交越） | 📄 需求規格 |
| FR-18 | 波德圖（dB 與展開後的相位，對數頻率軸） | 📄 需求規格 |
| FR-19 | 專案檔為 JSON（含 schemaVersion）；自動儲存與當機回復 | 📄 需求規格 |
| FR-20 | 匯入匯出 SPICE 子集網表；波形匯出 CSV（UTF-8 with BOM）與 SVG；電路圖匯出 SVG | 📄 需求規格 |
| FR-21 | 診斷頁：Newton 迭代次數、接受與拒絕步數、矩陣大小與非零數、分解耗時、採用的收斂方法 | 📄 需求規格 |

## 待確認的需求問題

這些項目規格沒有說清楚，開發時採用了預設處理（📄 依據：規劃文件「次要事項」，已經使用者同意「照建議進行」）：

1. **PULSE 省略 TR/TF 時的處理**：規格只寫「同 SPICE 定義」。
2. **電源只寫暫態波形、沒寫 DC 值時，直流工作點用什麼值**：採用 SPICE 語意，取波形在 t = 0 的值。
3. **開關在直流與交流分析中的狀態**：使用 `initial` 指定的狀態。
4. **被動元件支路電流的正方向**：採「由第一個接腳流向第二個接腳」。規格只定義了電壓源與電感。
5. **gmin 步進與電源步進**：仍未找到在預設迭代上限下「自然需要步進」的電路，目前以壓低迭代上限的方式測試（📄 `docs/TEST-REPORT.md` 第 7.4 節）。這是否足夠，需要驗收方判斷。
